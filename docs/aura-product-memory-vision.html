Current product contract

What AURA must do now.

The current app is not just a front-end. The experience depends on a mobile voice state machine, a backend orchestration layer, deterministic memory storage, emotional continuity context, and reminder delivery that changes based on foreground/background state.

Mobile shell

Expo iOS app named AURA, bundle id ai.aura.journal.recall, portrait-only, minimal grey-white UI, hidden controls, tap-to-speak interaction.

Backend brain

Express API on 0.0.0.0:4000. It owns STT, NVIDIA/OpenRouter replies, TTS, memory, recall, reminder parsing, check-ins, and provider key rotation.

Voice loop

Tap records. Tap again transcribes with Groq Whisper. NVIDIA or OpenRouter replies. Backend synthesizes Gemini or Pocket voice. iOS speech is the final device fallback.

Memory promise

Archive every user and assistant turn as historical truth. Extract smart memories and emotional signals separately. Exact dates appear only when the user wants exact recall.

Reminder promise

Reminder intent beats memory recall. Foreground app shows reminder text and speaks it. Background or closed app shows a normal AURA notification banner.

Build promise

A second Mac can run npm install && npm run ipa:ios. The build script regenerates iOS, validates permissions, patches Pods, and exports an unsigned IPA.

Backend API contract

The routes that make the app feel alive.

The mobile app is intentionally thin. These routes are the behavior contract a rebuild must preserve.

01

GET /health

Returns service status and provider readiness for OpenRouter, Groq, Gemini/Pocket voice, memory persistence, and archive paths.

02

POST /voice/transcribe

Receives multipart audio as audio. Logs file presence, MIME, size, transcript length. Returns transcript or clear failure.

03

POST /capture

Main brain route. Saves user turn, detects reminders/check-ins, decides recall mode, builds memory context, calls OpenRouter, stores reply, returns text plus voice when available.

04

POST /voice/synthesize

Reminder/standalone voice endpoint. Input { text }. Output { voice }. Voice may be Gemini, Pocket, or null; reminder creation must never fail because TTS failed.

05

GET /reminders

Returns scheduled reminders/check-ins for the app UI and local cache. Mobile schedules iOS notifications from these reminders.

06

POST /memories/session/finalize

Creates compact session summaries after idle gaps so long conversations are recallable without dumping every raw turn into normal prompts.

Failure rule: OpenRouter/Gemini failures degrade gracefully. AURA should still create reminders, save archive turns, and produce deterministic responses for greetings/capability checks when possible.

Voice pipeline

How AURA hears and speaks.

The voice path is the soul of the app. The rebuild must preserve the state order and the fallback chain.

Tap

Start recording

CaptureScreen records AAC/M4A using Expo AV. UI shows Listening in soft grey. If the user taps during playback, current audio stops and recording starts cleanly.

Tap

Stop and think

Second tap stops recording, validates URI/file, uploads to /voice/transcribe, then sends transcript to /capture. UI shows Thinking.

AI

Reply text first-class

When /capture returns, reply text appears on the background like a premium AURA reply. No card shape. No robotic transcript dump.

TTS

Voice starts as close to text as possible

Normal replies use Gemini voice if returned. If missing or playback fails, mobile uses the same loud iOS speech helper as reminders.

Primary STT

Groq Whisper via backend. This prevents mobile from needing provider keys and allows backend logging/retries.

Normal voice fallback

Mobile speakTextWithFailsafe chooses a clear installed iOS voice, volume 1, playsInSilentModeIOS, and a timeout unlock so the app does not stay stuck in speaking state.

Voice pipeline06
AURA
Gemini -> Pocket -> iOS

The current TTS resilience layer.

Gemini TTS can hit quota/permission limits. The current live state shows Gemini voice keys cooling down, so Pocket TTS is now the working backend fallback before the phone ever falls back to iOS speech.

1. Gemini
Backend tries all active Gemini keys, with cooldown for 400/401/403/429. /voice/synthesize uses a fast race across active keys for reminders.
2. Pocket TTS
If Gemini cannot produce audio, backend runs uvx pocket-tts generate. It converts the resulting WAV into raw PCM when possible so current mobile playback handles it.
3. iOS speech
If Gemini and Pocket both fail, the app speaks locally through the loud shared iOS speech failsafe. It uses volume 1, rate 1.08, silent-mode playback, and the same helper for chat, Type Instead, and foreground reminders.
Reminder voice behavior:
- app active: wait for backend voice until the end of the scheduled minute, max 59s
- if backend voice arrives: set reminder text and play prepared audio together
- if backend voice does not arrive by deadline: set text and speak with iOS fallback
- mark delivered only after text is visible and voice attempt finishes

Backend voice endpoint response:
POST /voice/synthesize { "text": "Hey Rihan, time to drink water." }
=> { "voice": { "audioBase64": "...", "mimeType": "audio/pcm;rate=24000", "provider": "pocket-tts" } }
=> or { "voice": null } when all backend TTS paths fail
Important: Background/closed app voice is not promised. iOS notifications show a banner only. Custom notification audio is intentionally not required because it can break delivery.

Reminder and check-in system

Foreground speaks. Background notifies.

Reminders are split into deterministic creation, local notification scheduling, and foreground voice delivery. Reminder intent must always beat memory recall.

Foreground/open app

Every second, App.tsx checks cached due reminders. If the app is active and not recording/speaking, it prepares voice, switches home, shows the reminder as normal AURA text, haptics fire, then voice plays.

Background/closed app

expo-notifications schedules a normal AURA text notification. No voice. When the app opens after a fired banner, markDueNotificationRemindersHandled prevents duplicate foreground voice spam.

Check-ins

“Ask me if I’m still smoking weed after 30 minutes” becomes a check_in reminder with a question and guidance. The answer is linked back and saved into memory.

Stuck-speech protection

If a previous reply leaves voiceBusy stuck, the stale unlock clears after 20 seconds so due reminders can still run.

Expected user flow:
User: remind me to drink water after one minute
AURA: Done, Rihan. I'll remind you at 01:40. Please keep AURA open around then so I can speak it to you.

At due time while app is open:
Screen text: Hey Rihan, time to drink water.
Voice: Gemini AURA voice -> Pocket TTS -> iOS fallback

At due time while app is closed/backgrounded:
Notification: AURA / Hey Rihan, time to drink water.
No background voice promise.

Memory architecture

Reliable recall is the core magic.

AURA has two layers: deterministic historical truth and derived intelligence. Never replace the archive with summaries. Summaries make recall fast; the archive keeps it honest.

Raw

Conversation archive

Every user transcript/text and every AURA reply is saved with exact timestamp, timezone, session id, input mode, role, and searchable text. This powers date-wise recall.

Smart

Smart memories

After each useful turn, memoryAnalyzer extracts summary, emotion, topics, goals, action signals, importance, tags, and memory layer.

Embed

Recall vectors

When configured, Gemini embeddings use gemini-embedding-001 and 1536 dimensions. If unavailable, keyword/recency fallback still works.

Idle

Session summaries

After roughly 5 minutes idle, mobile calls /memories/session/finalize. Backend summarizes recent archive turns into a session-summary memory.

UX rule: normal chat saves silently. AURA says “I heard you. I saved this moment.” only when the user explicitly says save/remember/journal this.
Memory architecture09
AURA
Recall modes

Exact when asked, subtle by default.

The major memory UX improvement is mode separation. AURA should not prove it remembers by dumping logs every turn.

Utility recall
Triggers on “what did I say”, “when did I”, “yesterday”, “last week”, “on May 14”, “show history”, exact timestamps, reminders, and explicit save commands.
Companion mode
Normal emotional conversation. AURA uses memory quietly: “You’ve seemed worn out lately,” not “You said tired on May 3, May 5...”
Archive answer
For date recall, conversationArchive.ts retrieves raw turns by date range/timezone and builds a clean answer hint. If no entries exist, AURA says so honestly.
Smart context
For normal replies, relevant smart memories, session summaries, emotional continuity, and theme scores are injected as quiet context, not visible logs.
Examples:
“What did I say yesterday?” -> utility mode, timestamped archive answer.
“What did I say today about Swift?” -> utility mode, filtered raw archive + summary.
“I’m tired again.” -> companion mode, maybe subtle continuity if repeated and cooldown allows.
“Remember this: I want to focus on fitness.” -> explicit save, one acknowledgement, smart memory.
Recall modes10
AURA
Emotional continuity layer

Memory that feels human, not creepy.

The emotional layer is derived context. It never overwrites historical archive truth. Its job is restraint, pattern awareness, and softer companion phrasing.

Signals

After capture, AURA detects soft labels like tired, stressed, sad, excited, calm, motivated, overwhelmed. Each signal has timestamp, confidence, topic, intensity, and source turn.

Theme scores

Repeated themes such as sleep, work, family, fitness, trading, money, study, relationship, loneliness, and goals gradually become more important.

Relationships

Lightweight person continuity tracks dad, mother, friend, girlfriend, cofounder-like mentions, tone, related topics, last seen, and recurrence.

Evolution

If the user says “I love trading” and later “I hate trading,” the archive keeps both. Companion mode treats the theme as changed or emotionally mixed.

Restraint

Cooldowns prevent AURA from mentioning the same pattern repeatedly. Low-confidence or sensitive patterns stay silent unless directly relevant.

Natural phrasing

Prompt context says: use continuity quietly, no timestamp dumps, no “I am analyzing your memory,” no forced therapy-bot behavior.

Goal: AURA should feel like a continuous presence that notices patterns over time, while still letting exact recall remain deterministic and trustworthy.

Failure diagnostics

When something breaks, start here.

Most failures fall into four buckets: provider quota, LAN networking, stale mobile cache/state, or iOS notification/voice behavior.

Network request failed
Check backend is running on 0.0.0.0:4000, phone is same Wi-Fi, Safari health works, and generated Info.plist allows local networking.
“AURA brain” failure
Usually OpenRouter key/model exhaustion. Add/rotate OPENROUTER_API_KEYS, use the free model route, restart backend, verify health key count.
No Gemini voice
Gemini TTS quota/permission may be exhausted. Backend should fall to Pocket TTS. If Pocket also fails, mobile iOS fallback should speak loudly via volume 1 and rate 1.08.
Reminder created but silent
Check Xcode logs for [AURA reminders]: due reminder found, preparing voice, visible text set, provider used, fallback used, delivered.
Foreground duplicate after banner
markDueNotificationRemindersHandled should mark reminders delivered when the app opens after a fired iOS notification.
Robotic recall
Verify recall mode: exact timestamps only in utility recall. Companion mode must use continuity context quietly.

Scale and revenue model

How AURA operates at 1,000 and then 10,000 users.

The subscription idea is $15/month with 100 user messages/day. The product must control AI usage so revenue covers LLM, STT, TTS, memory storage, and infrastructure.

Core assumption
100 user turns/day means about 3,000 LLM calls per user/month. Average context target is around 1,200 input tokens and 150 output tokens per reply.
Recommended voice mix
Pocket TTS primary, Gemini premium voice capped around 25% of replies, iOS speech emergency only. Gemini voice for every reply hurts margin.
1,000 users
Expected API cost about $3.6k-$4.0k/month, infra about $600-$900/month, total about $4.2k-$4.9k/month. Gross revenue is $15k/month.
10,000 users
Expected API cost about $36k-$40k/month, infra about $4k-$7k/month, total about $40k-$47k/month. Gross revenue is $150k/month.
Scaling strategy
Do not scale as one giant server. Split API nodes, brain workers, TTS workers, background memory jobs, Redis queues, and Supabase separately. Autoscale by queue depth and provider latency.
Hard guardrail
Do not sell unlimited AURA at $15. Enforce 100 turns/day, track cost per user, and degrade heavy users to cheaper models/Pocket voice/summarized responses before margin breaks.

Brain Lab - May 16, 2026

The eval system now protects intelligence, scale, and cost.

AURA now has a cost-safe backend evaluation framework called Brain Lab. It tests conversation quality, memory routing, cross-user isolation, drift, latency, queue behavior, and cost risk without turning every simulated message into a paid LLM call.

Single-user intelligence

npm run beta:real-user -- --stage=single runs one evolving 40-message user audit. Latest pass: router accuracy 97.78%, recall score 100%, drift 0%, cross-user leaks 0.

100-user mixed mode

--stage=100 --mode=mixed --real-users=15 --llm-max-calls=600 samples only selected users and critical paths. It tests distribution without a 4,000-call cost explosion.

1000-user structure mode

--stage=1000 --mode=structure makes zero LLM, STT, TTS, or external embedding calls. It tests routing, memory writes, reminder logic, queue stability, CPU/RAM, and leakage.

Sampled scale intelligence

--stage=1000 --mode=sampled --critical-only=true --llm-max-calls=300 validates a tiny critical-path brain sample under load while keeping provider cost bounded.

Replay cache

--replay-cache=write/read stores normalized replies and replays them for mock users. This makes regression runs repeatable and debuggable.

Failure injection

--failure-profile=light|medium|heavy uses test-only chaos headers to inject brain delay, brain failure, and memory delay for fake users only.
